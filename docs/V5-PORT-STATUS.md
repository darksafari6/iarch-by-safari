# Noctalia v5 port — experimental and incomplete

The current pull request branched from `30208a3`. The current `main` independently moved to Hyprland Lua and Noctalia v5 and added a minimaOS glass profile, Fedora installer, a different Arch installer and a rollback script. The PR's isolated v4 session uses Hyprlang, Quickshell, and `settings.json`. They are different architectures; resolving the conflicts by choosing one entire side would silently drop features or break the other workflow.

## Audit and priorities

1. **Installer safety:** the v5 `install.sh` runs as root, installs packages without confirmation, edits pacman repositories, enables services, overwrites configs, changes the display manager, and offers reboot. Main configuration deployment now stages only the v5 payload, checks backup destinations, stops on backup failure and restricts ownership changes to deployed paths; partial failure can still require manual recovery. Other flows, including optional backup restore, can alter user/system data and use recursive copy/chown. These effects need review and isolated tests; the v5 installer remains the existing system-wide workflow. The safer isolated installer is tied to v4 and is retained separately as `install-v4-session.sh`, not substituted for the v5 installer.
2. **Configuration and keybindings:** main uses `.config/hypr/*.lua`, `noctalia msg ...`, and `.config/noctalia/config.toml`; the branch uses `.conf`, `qs ...`, and `settings.json`. A mechanical merge can delete source files still required by the v4 installer, mix startup paths, and leave tests passing against the wrong architecture. The existing v4 customization center, diagnostics, recovery and tests are likewise not v5-compatible.
3. **Noctalia compatibility:** no installed Noctalia, Hyprland, live GUI, or audio/services are available here. Inspected upstream Noctalia v5.4.1 source commit `815aebe1cfd79c9a18197441eea92f0b275035fc`: TOML configuration, `noctalia --version`, and `noctalia config validate <directory>` are supported; v5 reads GUI-managed state overrides after config. Static inspection is not runtime validation. No v5 package or build has been installed.
4. **Glass and controls:** main already has a v5 palette and native shell profile. This branch copies those files, adds the upstream `tray` widget, changes the notification-sound default to off, and adds an opt-in, version-checked profile deployment helper. It does not implement a new Control Center, an airplane shortcut, or custom v5 notification sound. The existing v4 chime and v4 `--glass` installer are not v5 features. There is no guarantee GUI overrides do not enable sound.
5. **Validation:** source inspection and TOML parsing do not establish actual appearance, functionality, D-Bus ownership, hardware behavior or safety of the complete installers. Validate in a disposable Arch environment with real Noctalia, Hyprland, services and GPU before merging or release.

## Experimental v5 profile helper

`python3 tools/v5_profile.py --apply` requires a normal user, an existing Noctalia config-home directory, Noctalia **5.4.1**, and confirmation. Run outside the active Noctalia session. It makes a private staging copy of the existing `noctalia` directory, replaces only `config.toml` and `palettes/minimaOS.json` in that copy, and invokes `noctalia config validate` on the staged directory. On success it moves the original directory to a unique `noctalia.backup.<timestamp>.<random>` next to it and installs the staged copy. Unsafe symlinked target/managed paths are refused. Other files within the directory are preserved; GUI-managed state outside it is not modified and may override the profile. If the stage fails validation or deployment fails, the original stays in place or is restored. A failure that prevents restoring is reported with the backup location. No packages, services or login manager are touched.

For explicit rollback, again outside the active session, run `python3 tools/v5_profile.py --restore /full/path/to/noctalia.backup.NAME` using the actual backup. The selected backup is copied, not consumed; the current directory is moved to another backup. `NOCTALIA_CONFIG_HOME`, then `XDG_CONFIG_HOME`, then `~/.config` determine the config home; use an absolute path. This helper changes the selected Noctalia configuration, not the isolated v4 session. Do not use both shells as notification owners in one session.

**Tests:** `python3 -m unittest discover -s tests -p 'test_v5_profile.py'` uses temporary directories and a fake Noctalia executable. It covers preservation, rollback, rejected paths, invalid version, validation failure and injected rename failure. It does not test the actual Noctalia validator, Wayland, concurrent user edits, hardware, or the full Arch installer.

## Remaining work

The two installer workflows are kept distinct; v5 payload staging excludes v4 Hyprlang/JSON files. This is not a complete safety port: the v5 system-wide installer, rollback, customization, keybindings and hardware integrations require further review and real-session testing. Existing v4 customization tools and tests target only the v4 session.
