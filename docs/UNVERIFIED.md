# Unverified items

Every claim this repository makes about a feature must be either verified or listed here.
An item stays in this file until someone proves it on a real system and records how.
Code that depends on an unverified item carries a `TODO(verify)` comment pointing at its id.

Nothing in this file is a bug report or a wishlist. It is the boundary between
"checked" and "assumed".

**KB-04 was closed in this pass, and it was closed by being wrong.** The row said `Super+mouse_up`
and `Super+mouse_down` might not bind at all, because neither is a keysym in the pinned xkbcommon nor
a `mouse:N` code — both true, and both irrelevant, because there is a third path neither of the two
forms this record had verified covers. `CKey::isValidEvent` accepts `catchall`, a `mouse:` button, a
`switch:` state and exactly `mouse_down`, `mouse_left`, `mouse_up` and `mouse_right`
(`src/keybinds/Key.cpp:8-10`), and `CKeybindManager::onAxisEvent` turns a wheel delta into one of
those names and dispatches it as `SResolvedKey{.event = name}` (`src/keybinds/Manager.cpp:312-335`),
so the bind is matched on an event and never reaches `resolveKeycode`. The rejected row's own note had
already pointed at the answer — "if upstream supports it at all it is not through the key Forms this
record verified" — and it was right. Two limits came with the finding and are recorded in the new
form's `limit` rather than dropped: the four names are compared exactly, so `MOUSE_DOWN` is not the
same event, and `onAxisEvent` returns early unless the axis source is
`WL_POINTER_AXIS_SOURCE_WHEEL`, so a two-finger touchpad scroll never fires them. The row was deleted
from `rejected` and the mechanism added to `key_forms` as a fifth form; a rejection that source
disproves is removed rather than annotated, because that array is read as a list of spellings that do
not work. `iarch-keybinds check` reported two warnings after that pass instead of four, and the two
that remained were the `Super+Ctrl+Alt` layer debt on `move.next` and `move.previous` —
T4's to settle, and settled: allocating all 78 letter cells in
`data/design/keybinds.json -> alphabet` moved them to `Super+Ctrl+N` and `Super+Ctrl+P`,
so `check` now reports nothing at all on the shipped map and the rule that used to print
them guards the next bind that reaches for the recovery layer. What the table added in
their place is KB-06.

## How to close an item

1. Reproduce it on the target system (Arch or Fedora, real Hyprland session).
2. Record the command, the version and the observed result in the *Evidence* column.
3. Remove the `TODO(verify)` marker from the code that referenced the id.
4. Delete the row here in the same commit.
