# Unverified items

Every claim this repository makes about a feature must be either verified or listed here.
An item stays in this file until someone proves it on a real system and records how.
Code that depends on an unverified item carries a `TODO(verify)` comment pointing at its id.

Nothing in this file is a bug report or a wishlist. It is the boundary between
"checked" and "assumed".

Verification log for third-party license data: **2026-11-09**, upstream repository metadata and
`LICENSE`/`COPYING` files read through the GitHub REST API. Tooling: `tools/notices.py --check`.

Verification log for upstream APIs: **2026-11-09**, Noctalia `v5.4.1` docs and schema sources and
Hyprland `main` at `a1d7a78b` read through the GitHub REST API; the resulting load-graph and payload

## How to close an item

1. Reproduce it on the target system (Arch or Fedora, real Hyprland session).
2. Record the command, the version and the observed result in the *Evidence* column.
3. Remove the `TODO(verify)` marker from the code that referenced the id.
4. Delete the row here in the same commit.

| MOT-01 | The five motion presets in a live Hyprland session | Everything about them is checked statically and twice over: each preset validates against `data/schemas/animations_preset.schema.json`, and `gen_animations_lua.py` refuses a leaf, style, curve, bezier component, spring value or duration that `data/design/animations.json` — read out of Hyprland v0.57.2 source — does not allow. `hyprctl reload`, `hyprctl configerrors` and `luac -p` are exercised in `tests/test_iarch_anim.py` against a fake compositor and a fake compiler, because the development sandbox has no session, no `hyprctl` and no Lua binary. What has not happened is a preset being rendered on a machine where a window actually opens | Claiming a preset looks the way its `description` says, and the Part 3 acceptance items about windows opening in the chosen style, workspaces sliding and layers fading |
| MOT-02 | That a leaf set to `enabled = false` really stops moving, and does not stop its parent or siblings | The tree and its parent links are read out of `src/config/shared/animation/AnimationTree.cpp` and recorded per leaf in `data/design/animations.json`, and `hl.animation` is read to return early on `enabled = false` after `setConfigForNode(leaf, false, 1, "default")`. The renderer emits an explicit `false` for every disabled event precisely so it does not depend on inheritance, but whether a disabled child leaves its parent animating normally — `windowsIn` off while `windows` still slides, `specialWorkspace` off while `workspaces` still slides — was not observed | Claiming `minimal` and the per-event `toggle` do what their names say on screen |
| MOT-03 | How long a spring curve actually takes, and what its overshoot looks like | A spring's `duration_ms` is inert: `getCurveStep` advances it by wall-clock delta through `advanceSpring` and never reads `internalSpeed`, so the number emitted for a spring leaf satisfies the binding's `speed > 0` requirement and predicts nothing. The damping ratios quoted in the preset files (`smooth` 0.88, `snappy` 0.87, `bouncy` 0.67) and the overshoot percentages derived from them are textbook second-order-step arithmetic on the declared stiffness, damping and mass, not measurements of Hyprland's integrator, whose timestep and settling threshold were not read | Claiming a specific settle time or overshoot percentage for `windowsIn` |
| MOT-04 | Whether an overshooting bezier is clamped when the animated value is an opacity or a colour | `hl.curve` accepts a bezier component in `[-1, 2]`, so a curve that drives its value past the endpoint is legal, and `bouncy` uses two. On a `slide` or `popin` transform that past-the-endpoint value is a position, which is the intended look. On the `fade` family it would be an alpha above 1 and on `border` a colour channel outside its range, and whether Hyprland clamps those before compositing was not read out of this release — so `bouncy` deliberately uses overshoot curves only on the window arrival and the workspace switches, and `tests/test_animation_presets.py` asserts that no fade, layer or border event names one | Using an overshoot curve on any leaf that animates opacity or colour |
| MOT-05 | Whether `hyprctl configerrors` is empty in a stock session | `iarch-anim` compares the errors reported before a reload with the errors after it, rolls back only on lines that are new, and reports a pre-existing error as not ours. That comparison is correct whatever the baseline is, but the Part 3 acceptance criterion is written as "`configerrors` empty", which assumes a session this project did not configure starts clean — and no stock Arch or Fedora Hyprland session was queried to find out | Documenting an empty `configerrors` as the expected result on a fresh install |
