# Session themes

Part 1 of the six-theme pack. This file is the contract. It does not ship a theme.

The switch already exists. `iarch/cli/theme.py` is `iarch-theme apply`, and it already re-renders Hyprland glass, the Noctalia palette, GTK 3, GTK 4 and Kvantum from one preset, then reloads. A session theme is a new preset on that path. It is not a second bar, a second settings app, or a second command.

## The six ids

These ids are closed. Later parts must not add a seventh, and must not rename these.

| id | Session |
| --- | --- |
| `greenhouse` | Warm copper borders, wood-toned surfaces, bento overview, media dock with a bar visualizer |
| `amber-bloom` | Gold on near-black, hard edges, fast motion, pixel-style terminal colors |
| `neon-rain` | Magenta and violet night, pill Control Center, right-hand notification stack |
| `forest-night` | Near-black surfaces, green accent, short fades, no dock |
| `violet-glass` | Deep purple glass, long blur fades, on-screen keyboard uses the same surface |
| `crimson-silk` | Dark red surfaces, coral accent, yellow folders, compact bar, media dock |

`forest-night` is the default only when `~/.config/iarch/` has no saved theme choice. A later install must not overwrite a choice that is already there.

The user's choice is `~/.config/iarch/theme.json` with the shape `{"id":"<id>"}`. The repository holds defaults. Generated files do not hold the choice.

## What one apply changes

`iarch-theme apply <id>` is the only switch. Settings → Themes calls that same command. One apply updates all of these, from that preset alone:

- Hyprland border, rounding, gaps, blur, shadow, opacity, and the animation curves
- Noctalia bar, dock visibility, Control Center, notifications, and the palette file the shell already reads
- GTK 3 and GTK 4 accent overlays, and the Kvantum accent
- Kitty colors and the Starship palette
- The wallpaper path for that id
- The notification sound path and its volume

Game mode and focus mode still win. Turning either off restores the active theme, including its curves. A theme patch that breaks that is wrong.

## What this part does not do

- No `data/themes/<id>.json` packs yet. Those are Part 2.
- No wallpaper files, no sounds, no Settings page, no installer copy step.
- No hand edits to files that start with `-- GENERATED BY iArch. DO NOT EDIT.`
- No new notification daemon. The shell's notifier is the notifier.
- No copy of artwork or audio from reference screenshots. Assets, when they land, are original and credited in `THIRD_PARTY_NOTICES.md`.
- A widget that is not already a Noctalia widget is not built to imitate a screenshot. The existing widget is themed, and the gap is written down.

## Palette shape

Packs must fill the object `.config/noctalia/palettes/iarch-midnight.json` already uses: `dark` and `light`, the `m*` roles, and `terminal` with `normal` and `bright`. The generator writes `iarch-active` (or the palette path `iarch-theme` already writes). Nobody writes that file by hand.

Hyprland values stay in the design tokens `iarch/cli/gen_glass_lua.py` already renders into `.config/hypr/generated/glass.lua`. `.config/hypr/themes/theme.lua` stays the fallback for a session whose generated file is missing.

## Installer

`install.sh` and `fedora_install.sh` will learn the copy steps in a later part. They stay idempotent. A second run re-renders the saved id and does not change it. New files go through the existing manifest and the existing `.bak.<timestamp>` backup.

## Reload

Apply reloads the compositor and the shell the way `iarch-theme` already does. It does not restart the session. The greeter still changes only through `noctalia msg greeter-sync`, which this contract does not pretend the installer can skip.
